Background

Where the idea came from

The founder was inspired by BOINC, the Berkeley Open Infrastructure for Network Computing, a project at the University of California, Berkeley, since 2002.

If you have never heard of it: volunteers install a small app that uses their computer's idle time to work on real science. Einstein@Home searches for pulsars. Rosetta@home models proteins. Originally, SETI@home searched radio data. A server splits the work into chunks, sends them out, checks the results, and combines them.

SPIRA asks whether that same idea can train and serve an open language model.

SPIRA: Shared Pooled Intelligence for Research and AI is that question, as its own project. Volunteers would pool spare compute from their own PCs to train one capable, fully open language model together, then help serve it. There is no client yet. SPIRA is not part of BOINC, and it is not run by UC Berkeley.

The plan

How it works

Four stages, in order. Today there is an invitation, and no software.

  1. 01

    Donate compute

    You offer spare time on a PC you already own. When a client exists, you choose when it may run, and you can stop it. A GPU can help. Signing up now does not install anything or use your machine.

  2. 02

    Shared training

    Participating machines work on one model. Their progress is combined into a single set of weights. The work is shared. The result is not split into private copies.

  3. 03

    An open model

    The aim is a fully open release: weights, training approach, and code published so anyone can study them, run them, and build on them. Not an API a company can close.

  4. 04

    Community inference

    After a model exists, the same volunteer network helps serve it. Requests would be answered by computers people have chosen to share, rather than by a service you do not control.

The point

Why it matters

A capable language model is becoming shared infrastructure. The capable ones are mostly trained and held by a few companies. They can change the terms, hide the weights, or switch the service off.

SPIRA is a community project under the Afflatoria GitHub organization. It is an attempt to train one capable, fully open language model on spare compute that volunteers pool from their own PCs, and then to help serve it the same way. No company owns it. There is no token, and no plan to lock the model behind a paid API.

Open
Fully open means people outside the project can hold a copy of the weights and read the method. A demo behind a login is not the goal.
Not a company
Afflatoria is a community GitHub organization. There is no equity in the model and no owner who can take it private later.
Democratic, in a plain sense
The project is community-run. People who show up to build it do that in the open, rather than inside a company that can decide alone. That is not a claim that a vote of the internet will steer every training choice. It is a refusal to leave the model in a few hands.
One shared model
The point is a commons: one model the public can keep. Not a market of private models, and not a payout for spare cycles.

Related work

How this differs

Other groups have already done parts of this, and they have shipped real work. SPIRA has not. The difference is the arrangement, not a claim of better results.

Prime Intellect

Prime Intellect has trained models across computers on the public internet, and it has published work on low-communication training. It is a company with a platform. People contribute through that platform.

SPIRA has no company and no platform. The hope is spare capacity on PCs volunteers already own, given freely. Nothing here is running yet.

Nous Research, Psyche

Nous Research has run Psyche, a decentralized pretraining effort, and has published training methods that need very little bandwidth. That work comes from a research company, with its own roadmap and its own runs.

SPIRA is a volunteer community project. It does not have a training run, a client, or a lab behind it.

Petals

Petals lets people pool GPU memory to run and fine-tune large models that already exist. It is research software, and someone can join it today. Its main job is inference and fine-tuning.

SPIRA's first aim is to train one new open model as a community, and to help serve it after that. Petals is further along. We are naming a different aim, not competing with their result.

What is hard

Honest technical challenges

Training one language model on home PCs is an open research problem. Nothing below is built. These are the difficulties we already know are real, and the approaches worth trying.

Home connections are too slow

A normal training step wants to move a huge amount of data between machines. A home upload link cannot do that. Searches that split into independent chunks do not have this problem. Training one model does.

Approach Low-bandwidth methods in the family of DiLoCo: each machine takes many steps locally, then sends a small update, not every gradient.

Still open Whether those rare updates stay stable for a model large enough to be useful, on links that are slow and uneven.

Machines leave

A home PC will sleep, reboot, or be turned off. Dropout has to be normal, not a crash.

Approach Fault tolerance. Checkpoint often, let another machine finish abandoned work, and keep the run going when nodes drop out.

Still open Doing that without wasting most of the donated time.

The work has to be checked

A machine can be wrong by accident, or someone can send an update meant to spoil the model. Volunteers are not a trusted cluster.

Approach Verification. Repeat some of the work, reject updates that do not fit, and keep a smaller set of machines that can audit others.

Still open A check that is strong enough against a determined attacker and still cheap enough for spare hardware. This is not solved. A volunteer project should say so before it asks for trust.

The PCs do not match, and the data has to be legitimate

A model people would call capable does not fit on one consumer GPU. The honest start is a small public test. Splitting a larger model across ordinary PCs is research, not a feature we can promise.

Still open The training text also has to be lawfully usable, with a public recipe. That choice has not been made, and it will be made in the open.

Order of work

Roadmap

Tentative

An order of work, not a schedule. Putting dates on this would be fiction.

  1. Now

    Interest

    This page. Find people willing to offer a PC later, or to help design the system now.

  2. A public design

    Protocol, hardware assumptions, threat model, and data principles, written where anyone can argue with them.

  3. A first client

    A small open-source program that can join a toy run and leave without surprise. If you cannot read it, you should not run it.

  4. A small proof

    Train a modest model across a few home machines. Publish the weights and an honest account of what broke.

  5. A capable model

    Only if the proof holds. Size, data, and verification have to be earned one at a time.

  6. Shared inference

    Use the volunteer network to help serve the model, so using it does not require a company API.

Questions

FAQ

What is SPIRA?

SPIRA: Shared Pooled Intelligence for Research and AI. Volunteers pool spare compute from their own PCs to train one capable, fully open language model together, then help serve it. It is community-run, at the idea stage, and there is no client yet.

Can I install something today?

No. There is no client. The form is a way to say you want to take part when there is something real to run, or that you want to help build it.

Is this cryptocurrency?

No. There is no token, no wallet, and no payout. Spare compute would be a donation.

Who controls the project?

It is community-run, hosted by the Afflatoria GitHub organization. It is not a company. Design, data, and the license should be argued in the open by the people doing the work.

Who owns the model?

No model exists. The intention is a fully open release the public can keep, not a weight file locked to one organization. The exact license is not chosen yet.

Will it slow down my PC?

Nothing runs on your PC today. The aim, once a client exists, is spare capacity only, under your control. That still has to be built and tested.

What hardware do I need?

You do not need a specific machine to register interest. A GPU is useful. An older PC may still matter for early tests. Real minimums will be published before anyone is asked to run code.

Where did the idea come from?

The founder was inspired by BOINC, the Berkeley Open Infrastructure for Network Computing, at UC Berkeley since 2002. Volunteers install a small app that uses idle time for scientific work, and a server splits that work into chunks, checks the results, and combines them. SPIRA asks whether that same idea can train and serve an open language model. The longer note is in Where the idea came from.

Why the name?

From Latin spiritus and spirare: breath, or spirit. One mind, made from many breaths.

What happens to my email?

The form sends it to a Formspree inbox for this project, so we can reply. If you opt in, we may write when there is something to report. This page loads no advertising trackers, and we do not sell the list.

When does training start?

No date. A public design and a small proof come first. The roadmap is tentative.

How do I help if I do not have a powerful PC?

Choose Help build it. Machine learning, distributed systems, the website, design, and community organizing all matter before a training run does.
